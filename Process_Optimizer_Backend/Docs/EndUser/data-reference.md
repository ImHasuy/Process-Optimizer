# Data reference

## Field formats

| Kind | Format | Notes |
|---|---|---|
| Ids (`id`, `projectId`) | GUID, e.g. `af9a4f9f-acac-4192-ba41-801d2280b589` | Generated by the API. |
| Scenario indexes | 64-bit integer ≥ 0 | At most 2^53 − 1 scenarios are indexable, so every index fits exactly into a JavaScript number. |
| Timestamps | ISO-8601, always **UTC** | The envelope `date` ends with `Z`. Stored timestamps (`createdAt`, `updatedAt`) read back from the database are written **without** the `Z` suffix, e.g. `2026-10-10T19:14:26.6588775`; treat them as UTC. |
| Durations | decimal ≥ 0 | In the project's `timeUnit`. |
| Costs | decimal ≥ 0 | In the project's `currency`. |
| Decimals in JSON | JSON number | The same value may be written as `25000` or `25000.0`; compare numerically. |
| Currency | three upper-case letters (`^[A-Z]{3}$`), ISO 4217 | Default `EUR`. |
| Names | 1–100 characters after trimming | Stored trimmed. Uniqueness ignores case and surrounding spaces. |
| Description | up to 1000 characters | Optional. |
| Enums | strings (names below) | Sent and returned as strings; enum names in query strings and JSON are matched case-insensitively. |

## Enums

### ETimeUnit

Unit of every duration of a project.

| Value | Meaning |
|---|---|
| `Minutes` | Durations are minutes. |
| `Hours` | Durations are hours. |
| `Days` | Durations are days (default). |
| `Weeks` | Durations are weeks. |

### EResourceLimitBasis

| Value | Meaning |
|---|---|
| `Planned` | Use `po:duration` of every node (default; this is the converted `time` of a frontend JSON save). |
| `Pessimistic` | Use the `pessimistic` value of `po:estimate` for nodes that have an estimate, `po:duration` otherwise. Costs are unchanged. |

### EFlowNodeKind

Normalised kind of a BPMN flow node (`kind` in scenario activities, `gatewayKind` in scenario choices).

| Value | BPMN elements |
|---|---|
| `StartEvent` | `startEvent` |
| `EndEvent` | `endEvent` |
| `Task` | `task`, `userTask`, `manualTask`, `serviceTask`, `scriptTask`, `businessRuleTask`, `sendTask`, `receiveTask` |
| `SubProcess` | `subProcess` (not an event sub-process); counted as one activity, its inner elements are ignored |
| `CallActivity` | `callActivity` |
| `IntermediateEvent` | `intermediateCatchEvent`, `intermediateThrowEvent` |
| `ExclusiveGateway` | `exclusiveGateway` (XOR) |
| `ParallelGateway` | `parallelGateway` (AND) |
| `InclusiveGateway` | `inclusiveGateway` (OR) |
| `EventBasedGateway` | `eventBasedGateway`; behaves like an exclusive split whose choice is not controllable |

Activities are `Task`, `SubProcess` and `CallActivity`. Not supported (error `DV-04`): `complexGateway`,
`boundaryEvent`, `transaction`, `adHocSubProcess` and event sub-processes (`subProcess triggeredByEvent="true"`).

## The `po:` BPMN extension

Durations, costs and related data are attributes and elements in the namespace
`http://projectoptimizer.app/schema/bpmn/1.0` (conventionally prefixed `po`), placed on the flow-node elements of
the BPMN process. A frontend JSON save writes `po:duration` and `po:cost` for you (converted from `time` and
`price`) and keeps the original texts in `optimizer:time` / `optimizer:price` (namespace
`http://process-optimizer.com/schema/1.0/bpmn`, informational only). When you save BPMN XML yourself, add them as
in this excerpt (sequence flows and events omitted):

```xml
<bpmn:definitions xmlns:bpmn="http://www.omg.org/spec/BPMN/20100524/MODEL"
                  xmlns:po="http://projectoptimizer.app/schema/bpmn/1.0" id="Definitions_1">
  <bpmn:process id="Process_1">
    <bpmn:task id="A" name="Design" po:duration="5" po:cost="4000">
      <bpmn:extensionElements>
        <po:estimate optimistic="3" mostLikely="5" pessimistic="10" />
        <po:crashOption duration="3" cost="6500" />
      </bpmn:extensionElements>
    </bpmn:task>
    <bpmn:task id="D" name="Test" po:duration="4" po:cost="2000" po:parallelizable="false" />
  </bpmn:process>
</bpmn:definitions>
```

| Item | Format | Default | Meaning |
|---|---|---|---|
| `po:duration` | number ≥ 0, `.` as decimal separator | `0` (warning `DV-10` on activities) | Duration in the project's time unit. Any flow node may have one (e.g. a gateway "approval meeting"). |
| `po:cost` | number ≥ 0 | `0` (warning `DV-10` on activities) | Cost in the project's currency. |
| `po:parallelizable` | `true` / `false` | `true` | Read on activities only. `false` = exclusive: the activity must not overlap with any other activity (it needs a single shared resource). |
| `po:estimate` (in `extensionElements`) | `optimistic ≤ mostLikely ≤ pessimistic`, each ≥ 0 | none | Three-point estimate; `pessimistic` is used by `basis=Pessimistic`. |
| `po:crashOption` (0..n, in `extensionElements`) | `duration` < normal duration, `cost` ≥ normal cost | none | A faster, more expensive way to do the activity. Only checked (`DV-09`); not used in any response yet. |

Invalid values are counted as `DV-09` errors; an invalid duration or cost counts as missing (0), so the activity
also gets the `DV-10` warning.

## Diagram validation codes

Every saved diagram is checked against these rules. No endpoint returns the individual issues: the diagram only
exposes how many there are, as `errorCount` (severity Error) and `warningCount` (severity Warning), and
`isOptimizable` is `true` exactly when `errorCount` is 0. While the diagram has errors, the scenario,
and resource-limit endpoints answer 409. The table explains what the counts count; the message
column gives the rule's internal message, and the last column the element it concerns.

| Code | Severity | Rule | Concerns |
|---|---|---|---|
| `DV-01` | Error | `The diagram must contain exactly one process.` / `The process must not be empty.` | the whole diagram / the process |
| `DV-02` | Error | `The process has no start event.` | the whole diagram |
| `DV-03` | Error | `The process has no end event.` | the whole diagram |
| `DV-04` | Error | `The element type '<element>' is not supported.` | the element |
| `DV-05` | Error | `The sequence flow references the missing or unsupported flow node '<id>'.` (the flow is ignored) | the sequence flow |
| `DV-06` | Error | `The node is not reachable from a start event.` | the node |
| `DV-07` | Error | `The node does not reach an end event.` | the node |
| `DV-08` | Error | `The node is part of a cycle.` | each node of the cycle |
| `DV-09` | Error | `The value '<value>' of po:duration must be a finite number greater than or equal to 0.` (same for `po:cost`) / `The value '<value>' of po:parallelizable must be 'true' or 'false'.` / `The estimate must satisfy optimistic <= mostLikely <= pessimistic.` / `A crash option must be faster than the normal duration and not cheaper than the normal cost.` In a frontend JSON save, a `time` or `price` that could not be converted (e.g. `25 USD` in a EUR project) lands here. | the node |
| `DV-10` | Warning | `The activity has no po:duration or no po:cost; 0 is assumed.` | the activity |
| `DV-11` | Error | `The gateway has several incoming and several outgoing sequence flows; model it as two gateways.` | the gateway |
| `DV-12` | Error | `The split has no matching join of the same type, or the region between them is not single-entry single-exit.` | the split (or the whole diagram) |
| `DV-13` | Warning | `The node has several incoming or outgoing sequence flows and is interpreted as a parallel join or split; use an explicit parallel gateway.` | the node |
| `DV-14` | Warning | `The condition is ignored because the sequence flow does not leave an exclusive or inclusive split.` | the sequence flow |
| `DV-15` | Warning | `Several nodes share the name '<name>'.` | each node with that name |
| `DV-16` | Warning | `The inner elements of the expanded sub-process are ignored.` | the sub-process |
| `DV-17` | Error | `An inclusive split may have at most 10 outgoing branches.` | the gateway |

`DV-12` is only checked when none of the other errors is present. Every split must be closed by a join of the same
type (an exclusive or event-based split by an exclusive join, an inclusive split by an inclusive join, a parallel
split by a parallel join or an implicit join), with a single-entry single-exit region in between.

## Scenario keys and indexes

- **Count.** Parallel branches multiply, exclusive (and event-based) branches add up, an inclusive split with
  branches b₁…bₘ offers every non-empty subset of branches.
- **Key.** One `gatewayId=targets` entry per choice, in enumeration order, separated by `;`. For inclusive
  choices the targets are joined with `+`. A target is the `bpmnId` of the first node of the chosen branch.
  Choices inside branches that were not taken are omitted. Examples: `Split=Fast`, `G3=E;G5=B+C`. A diagram without
  choices has exactly one scenario with the key `""` (empty string).
- **Index.** Scenarios are numbered 0 … count − 1 in a fixed order (`orderingVersion` 1): branches are ordered by
  the `bpmnId` of their first node; index 0 is "the first branch everywhere". The same diagram and index always
  give the same scenario. An index belongs to one version of the diagram and may change when the diagram is
  saved again; the key stays meaningful and can be looked up in the new version.

## Limits

| Limit | Value | Effect when exceeded |
|---|---|---|
| Diagram XML size | 2 MB (2 097 152 UTF-8 bytes) | 400 on save |
| Diagram save request body | 3 MiB | 413 on save |
| Flow nodes per diagram | 1000 | 400 on save |
| Branches of an inclusive split | 10 | `DV-17` error |
| Indexable scenarios | 9 007 199 254 740 991 (2^53 − 1) | 409 on scenario-indexed endpoints; resource limits without scenario references |
| Scenarios in one list response | 1000 | 409 on `GET …/scenarios`; request them one by one with `GET …/scenarios/{index}` |
| Project name / description | 100 / 1000 characters | 400 |
| Frontend JSON: id, source, target / state type, branch type / time, price / names, condition | 255 / 100 / 100 / 1000 characters | 400 |
